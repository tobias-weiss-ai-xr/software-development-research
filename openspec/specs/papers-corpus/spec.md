# papers-corpus Specification

> Source files: `papers.yaml`, `scripts/validate_papers.py`, `scripts/generate_readme.py`, `scripts/standard_stats.py`, `scripts/analysis/generate_reports.py`, `scripts/research_config.py`, `AGENTS.md`, `.github/workflows/validate.yml`
> Contract enforcer: `scripts/validate_papers.py` — SHALL exit 0 before any commit.
> Test suite: `tests/` (pytest) — verifies the contract layer independently of the corpus data.
> Last updated: 2026-08-25

## Purpose

Define the canonical contract of a `*-research` corpus: the `papers.yaml`
data model, the validation gates every paper entry MUST pass, the generated
artifacts, and the agent workflow guardrails that keep the corpus trustworthy
and machine-checkable. This is the **spec** layer of the spec–contract–test
pyramid; `scripts/validate_papers.py` is the **contract** enforcer; `tests/`
is the **test** layer.

## Requirements

### Requirement: Single Source of Truth

The corpus SHALL be defined entirely by `papers.yaml` plus `config/taxonomy.yaml`.
Every script SHALL read the taxonomy via `scripts/research_config.py`; no script
SHALL hardcode category or subcategory names.

#### Scenario: Taxonomy lives in one place

- **GIVEN** a change to categories, subcategories, or queries
- **WHEN** any pipeline script or tool runs
- **THEN** it SHALL pick up the change from `config/taxonomy.yaml` via `research_config.py`
- **AND** no script SHALL contain hardcoded taxonomy values

#### Scenario: Generated files are never hand-edited

- **GIVEN** `README.md`, `docs/papers.json`, `statistics.json`, or `docs/research/*.md`
- **WHEN** an agent or human edits the corpus
- **THEN** those files SHALL be regenerated by the pipeline, never edited by hand
- **AND** `README.md` SHALL only be written by `scripts/generate_readme.py`

### Requirement: papers.yaml Data Model

Each entry in `papers.yaml` under the `papers` key SHALL be a mapping with at
least `title`, `date`, `url`, `category`, `subcategory`. The `date` SHALL match
`YYYY-MM` and SHALL NOT be in the future. The `url` SHALL start with `https://`.

#### Scenario: A valid paper entry passes

- **GIVEN** a paper mapping with a real title, a `YYYY-MM` date, an `https://` URL, and values from the configured taxonomy
- **WHEN** `scripts/validate_papers.py` runs
- **THEN** it SHALL report no errors

#### Scenario: Missing required field fails

- **GIVEN** a paper entry missing `title`, `date`, `url`, `category`, or `subcategory`
- **WHEN** validation runs
- **THEN** validation SHALL report an error naming the missing field

#### Scenario: Taxonomy violation fails

- **GIVEN** a paper entry whose `category` or `subcategory` is not defined in `config/taxonomy.yaml`
- **WHEN** validation runs
- **THEN** validation SHALL report an error citing the allowed values

#### Scenario: Future date fails

- **GIVEN** a paper entry dated after the current month
- **WHEN** validation runs
- **THEN** validation SHALL report a future-date error

#### Scenario: Duplicate entry fails

- **GIVEN** two entries with the same title, category, and subcategory
- **WHEN** validation runs
- **THEN** validation SHALL report a duplicate-entry error referencing the first occurrence

### Requirement: URL Normalization Contract

arXiv URLs SHALL use the canonical form `https://arxiv.org/abs/XXXX.XXXXX`
(no `pdf`, no `doi.org/10.48550`, no `www.`).

#### Scenario: Non-normalized arXiv URL

- **GIVEN** a paper whose `url` points at arXiv in any non-canonical form
- **WHEN** validation runs without `--fix`
- **THEN** validation SHALL report a normalization error
- **WHEN** validation runs with `--fix`
- **THEN** the URL SHALL be rewritten to the canonical form

### Requirement: LaTeX Artifact Hygiene

Paper `title` and `abstract` SHALL be free of LaTeX markup artifacts
(`$...$`, `\(...\)`, `\textit{...}`, etc.).

#### Scenario: Artifact warning

- **GIVEN** a title or abstract containing a LaTeX artifact (without false positives on legitimate `$`-free text)
- **WHEN** validation runs without `--fix`
- **THEN** validation SHALL emit a warning
- **WHEN** validation runs with `--fix`
- **THEN** `clean_latex_artifacts` SHALL strip the artifact

### Requirement: Pipeline Contract

The pipeline SHALL be: validate → generate README → compute stats → generate
reports. It SHALL be runnable end-to-end with a single chain of commands and
SHALL fail loudly on error.

#### Scenario: Full pipeline passes

- **GIVEN** a `papers.yaml` that passes validation
- **WHEN** the pipeline runs
- **THEN** `README.md`, `docs/papers.json`, `statistics.json`, and `docs/research/*.md` SHALL be regenerated consistently

#### Scenario: README drift is detected

- **GIVEN** a `README.md` that does not reflect the current `papers.yaml`
- **WHEN** `scripts/generate_readme.py --check` runs
- **THEN** it SHALL exit non-zero, signaling the README is out of date

### Requirement: Agent Workflow Guardrails

The repo SHALL be safe for autonomous agents: no invented papers, validation
before commit, and full pipeline re-run after any `papers.yaml` change.

#### Scenario: Agent adds paper safely (AGENTS.md contract)

- **GIVEN** an agent following `AGENTS.md`
- **WHEN** it wants to add a paper
- **THEN** it SHALL verify the paper exists, deduplicate against title and arXiv id/URL, use only taxonomy-defined category/subcategory values, and run the full pipeline
- **AND** validation SHALL exit 0 before the change is committed

#### Scenario: No invented papers

- **GIVEN** any proposed `papers.yaml` change
- **WHEN** the entry is added
- **THEN** it SHALL have a real, verifiable `https://` URL
- **AND** no fabricated entries SHALL be committed

### Requirement: Continuous Verification (CI)

CI SHALL enforce the contract on every push touching the corpus, the scripts,
or the config, and SHALL fail the build on any violation.

#### Scenario: Validate job gates the push

- **GIVEN** a push or pull request touching `papers.yaml`, `scripts/`, `config/`, or `requirements.txt`
- **WHEN** CI runs
- **THEN** `validate_papers.py` SHALL exit 0
- **AND** `generate_readme.py --check` SHALL confirm the README is in sync
- **AND** the pytest suite SHALL pass
- **AND** on a `main` push the generated site SHALL be deployed to GitHub Pages

### Requirement: Test Layer

The test suite SHALL verify the contract functions on synthetic data without
network access, so it runs fast and hermetically in CI and locally.

#### Scenario: Tests are hermetic and fast

- **GIVEN** the pytest suite in `tests/`
- **WHEN** it runs (no network)
- **THEN** it SHALL pass quickly against synthetic papers and the real config
- **AND** no test SHALL require the corpus to contain specific real papers
